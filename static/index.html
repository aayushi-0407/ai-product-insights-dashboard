How this works

Methodology

End-to-end pipeline, from raw reviews to the numbers on screen — including where it's a real production-shaped system and where it's a portfolio-scale simplification.

01
Ingestion
Reviews come from McAuley-Lab/Amazon-Reviews-2023's raw_review_Software split on Hugging Face — a real, public dataset, not synthetic data. Each review has no native ID, so one is derived by hashing asin + user_id + timestamp + title + text, which also makes re-ingestion idempotent (dedupes on that hash).
02
Chunking
Fixed-size token windows (300 tokens, 30 overlap). Amazon Software reviews are short, so this collapses to one review = one chunk in the normal case; only unusually long reviews actually split.
03
Embeddings
Local sentence-transformers/all-MiniLM-L6-v2 (384-dim), stored in a Chroma vector database. Chosen over a hosted embedding API to keep the deployed image self-contained and free to run.
04
Theme discovery
HDBSCAN over the embeddings — density-based, so it doesn't need a pre-chosen number of clusters and correctly leaves outlier reviews unclustered ("noise") instead of forcing every review into a theme. A Groq-hosted LLM (llama-3.3-70b-versatile) then names each cluster from its nearest-to-centroid sample reviews.
  • Known limitation: naming from only 3 sample reviews can misfire — one theme in this build is labeled "Positive User Experience" but is actually mostly 1-2★ reviews, because its 3 sampled reviews happened to read positively. Left visible rather than hidden, since it's a real characteristic of this approach worth being honest about.
05
Product enrichment
The review split alone carries no product name, only an opaque asin/parent_asin. A one-time join against raw_meta_Software (streamed once, filtered down to the ~800 products actually in this corpus) resolves real product titles for citations and the top-complaints list — see scripts/build_product_titles.py.
06
Outcomes & pain index
Each theme gets a scorecard: review count, average rating, % negative (1-2★), growth rate, and a pain index = count × [(negative% × 1.5) + max(0, (3.5 − avg_rating) / 3.5)] × 20 — volume × severity, with no CSAT/churn/SLA-breach fields to draw on (those are support-ticket concepts; this is review data), so severity is built from rating and negative share instead. Weights are explicit and tunable, not derived from anything external. Growth is anchored to the corpus's own most recent review date, not wall-clock time, since this is a static historical bulk load rather than a live feed.
07
Storage split
Postgres (Neon) answers aggregation questions — everything on this dashboard is a real GROUP BY query, not post-processed JSON. Chroma answers similarity questions for Ask Signal. This split matters: a vector database is the wrong tool for "top 10 by count" or "trend over time," and a relational GROUP BY is the wrong tool for "find reviews like this one" — each store only does what it's actually good at.
08
Ask Signal (self-correcting RAG)
An explicit LangGraph graph: retrieve → grade → [rewrite → retrieve] → generate → verify. Retrieved chunks are graded for relevance in a single batched Groq call (not one call per chunk); if nothing relevant comes back, the query is rewritten and retried before generating. The streaming chat endpoint trades that retry loop for immediacy — a retry can't un-send tokens already streamed to the browser — while the non-streaming /ask endpoint keeps the full self-correction path for programmatic callers. Every claim in an answer is required to cite a specific review, resolved to its real product name rather than a bare ASIN.
09
Assumptions & limitations
  • This is a single static historical bulk load (~1,000 reviews spanning 2000-2023), replayed as if ingested in order — not a live feed.
  • No real subscription-tier data exists in this dataset split; anywhere a "premium/free" signal is implied, it would need to be bootstrapped from rating, which is a synthetic stand-in, not real billing data.
  • Cluster naming can mismatch cluster content (see step 04) — themes are discovered from language, but named by a small, imperfect sample.
  • "Create ticket" is a UI demonstration only: it does not call a real Jira instance or create anything outside this browser tab.
